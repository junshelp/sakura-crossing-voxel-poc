## Required Behavior

- Add a public benchmark entry and JSON download in the HUD. One standard run
  contains six legs in alternating Baseline/Voxel order, three per mode. Export
  each leg and aggregate medians. Use one application session.
- Each leg uses exactly 1600 × 900 internal rendering resolution, DPR 1, a
  five-second warm-up and thirty-second measurement. Route through the three
  existing fixed cameras at deterministic equal intervals; replay the same
  initial train offset and deterministic simulation progression per mode.
- Keep the deterministic route/state identical across all six legs, including
  warm-up. Use real uncapped frame durations for measured p50/p95/mean; never
  report the gameplay dt clamp or invented GPU timing as performance evidence.
- Exclude mode mount, warm-up, and interval-straddling samples; use clear boundary
  semantics tested with synthetic frame timestamps. Abort/invalidate a run on
  visibility loss or context loss instead of retaining contaminated results.
- Disable movement, mode/marker switches, and interactions during measurement.
  Save and restore the user's player pose, marker, mode, and simulation snapshot
  on success, cancel, or failure. Restore viewport and device-pixel ratio too.
- Record per-leg sample count, p50/p95/mean frame ms, median draw calls,
  triangles, texture count, shader-program count, mount/build ms, and generated
  geometry bytes. Include a versioned JSON schema and input validation.
- Record Reference Profile fields: profile name, browser/user agent, platform,
  hardware/renderer information when exposed, viewport/DPR, timestamp, seed,
  application source commit and dirty-build status, and user-entered hardware/
  power context. Unknown values must be explicitly unknown, never invented.
- Include optional disjoint GPU timer data only if implemented correctly with
  asynchronous query polling and cleanup; otherwise report supported/unsupported
  or not-measured with null values. It must never block rendering or be labeled
  as CPU frame time.
- Provide an explicit short diagnostic run for CI (e.g. 0.2 s warm-up + 0.6 s
  sample per leg). Mark its JSON diagnostic=true so it cannot pass formal
  acceptance. Standard durations stay unchanged.
- Provide a reusable browser capture script, using the application's real
  benchmark UI and download, to retain a complete production JSON run. Root will
  run standard measurement independently and record actual evidence.
- Evaluate the PRD thresholds explicitly: ≥50% median draw-call reduction,
  ≥20% p95 improvement; secondary profile regression ≤10%. Unknown/missing
  profiles and diagnostic runs must remain inconclusive. Failing thresholds
  yields revise; it does not cause CI absolute-performance failure.
- Add explanatory measurements for source line count, serialized Voxel Asset
  bytes, generated mesh bytes, production bundle bytes, and build time. Clearly
  state the local Baseline control does not measure upstream source-code savings.
- Production Playwright smoke must serve the built `dist` (not Vite dev), cover
  both modes/interactions, and download/validate diagnostic benchmark evidence.
- Update README with actual install/run/test/control/benchmark instructions and
  known limitations. Add a final evidence report template for root to fill with
  measured results, Functional Parity, Visual Acceptance pending, and next action.
- Add GitHub Pages deployment readiness as a workflow gated by an explicit
  repository variable such as ENABLE_PAGES_DEPLOYMENT == 'true', with default
  branch push/manual triggers and standard build/upload/deploy stages. The
  variable and Pages settings remain unchanged. A push must not deploy while
  the gate is unset. Keep the existing relative asset base working.

## Acceptance Criteria

- Unit tests independently validate percentiles, finite/empty samples, warm-up
  exclusion, straddling boundaries, durations, alternating order, schema fields,
  invalidation, viewport normalization, and threshold/inconclusive conclusions.
- Browser smoke verifies a production build, both modes, completed diagnostic
  download, all six ordered legs with metrics, diagnostic labeling, and restore
  of user mode/player/simulation state. Test cancellation/restoration as well.
- Three standard legs per mode can be retained and compared from the same
  production session with reproducible metadata. Root owns final captured files.
- No invented Reference Profile or successful performance claim. Human Visual
  Acceptance and any unavailable physical secondary hardware remain explicit.
- Full prior test suite remains green; no renderer quality/performance changes.

The root review in `reviews/W007.md` found incomplete verification and incorrect
measurement lifecycle. Correct through two disjoint workers:

- Domain worker: only `src/benchmark/**`, `tests/benchmark/**`, and
  `results/W007-domain.md`. Own strict schema/statistics/thresholds and pure
  interval sampling/camera scheduling tests.
- Runtime worker: the remaining original Allowed Scope except `docs/evidence/**`
  (root-owned), and `results/W007-runtime.md`. Own the single frame driver,
  production integration/download/restoration tests, capture/metrics scripts,
  metadata controls, deployment gate, and docs/template.
- Root: independent final verification, actual benchmark JSON and screenshots
  in `docs/evidence/**`, final report, merged result/review, commit/push.

Coordination API: retain public `LegMetrics`/`BenchmarkReport` field names;
domain adds `FrameSampler(startMs, durations)`,
`add(previousMs, nowMs, {frameMs, drawCalls, triangles, textureCount, shaderProgramCount})`,
`summarize(mode, index, mountMs, generatedGeometryBytes)`, and
`cameraMarkerAt(elapsedMs, durations)` (Overview warm-up, sample-time thirds).
The runtime supplies metrics from the preceding rendered frame interval and
uses the domain sampler's whole-interval boundary checks. Workers may coordinate
compatible additive API details but must retain disjoint file ownership.
