# W004 Task — Baseline Mode Playable Slice

## Goal

Replace the Baseline tracer boxes with a coherent conventional-procedural
Japanese suburban crossing scene built from the Shared Scene Specification.
Add shared, renderer-independent first-person state, flat-space collision,
fixed comparison cameras, lighting, and live renderer telemetry. Voxel Mode may
remain a tracer until W005.

## Required Behavior

- Implement a `BaselineAdapter` that consumes the existing immutable
  `SharedSceneSpecification` and creates conventional Three.js procedural
  visuals with stable semantic names. It must not define gameplay colliders,
  interactions, or simulation state.
- Render the complete approved inventory: one recognizable crossing rig, one
  two-car train, corner shop, two visually distinct houses, vending machine,
  relay box, utility poles, fence, four cherry trees, restrained petals, and a
  parked bicycle. Shared road, footway, rails, wires, and planet remain owned by
  Continuous Infrastructure and must not be duplicated by the adapter.
- Use modest reusable geometry/materials and one small named palette. Avoid one
  unique material per object and dispose all adapter-owned resources exactly
  once.
- Give the crossing stable child names for barrier pivots and warning lights,
  and the train stable car names/pivots so W006 can animate them. Keep W004's
  rigs in a deterministic initial state; do not implement train/crossing timers,
  relay/vending behavior, or simulation state.
- Seat baseline entity groups rigidly on the planet through the W003 world API.
  Preserve local pivots for future animation and ensure upright orientation at
  representative non-origin positions.
- Add shared lights suitable for conventional materials. Lights belong outside
  either adapter and survive mode switches.
- Implement renderer-independent player state in authored flat coordinates:
  player x/z, eye height, yaw, and pitch. Project the camera to the sphere each
  frame using the local east/up/north basis.
- Implement first-person WASD/arrow movement and pointer-lock mouse look. Clamp
  pitch and keep the player inside the 60 x 60 m populated footprint.
- Resolve player movement against Shared Scene Specification colliders in flat
  x/z using a documented player radius. The ground is support, not an obstacle;
  crossing/train animation is not part of W004. Collision logic must be pure or
  independently testable and must never read baseline render objects.
- Mode switching must preserve player/camera state and Continuous
  Infrastructure. Voxel Mode may still show its tracer, but the shared player
  controls and camera must continue to operate.
- Support all fixed comparison markers from the Shared Scene Specification via
  visible controls or documented keys, and expose the active marker in a stable
  DOM hook. Activating a marker updates shared player/camera state rather than
  replacing the camera.
- Extend the HUD with unobtrusive live mode, frame-time, draw-call, and triangle
  telemetry plus concise movement/mouse/fixed-camera guidance. W007 owns formal
  sampling, percentiles, JSON export, and acceptance thresholds.
- Preserve an accessible, usable UI at desktop sizes and do not cover the
  central comparison view.

## Acceptance Criteria

- Unit tests prove that Baseline Mode emits every required semantic entity with
  stable names, exactly two train cars, reusable bounded material identities,
  named crossing pivots/lights, and no duplicated Continuous Infrastructure.
- Unit tests prove representative entity seating position/orientation and that
  child pivot transforms survive seating.
- Player tests cover forward/strafe movement, yaw/pitch clamping, footprint
  bounds, collision rejection/sliding around at least a building and pole, and
  exclusion of the ground collider as an obstacle.
- Tests prove player/collision code consumes Shared Scene Specification data and
  does not depend on Baseline renderer objects.
- Adapter disposal tests prove owned geometries/materials are released and
  shared resources are not disposed.
- Browser smoke verifies Baseline content inventory hooks, visible telemetry,
  a fixed-camera change, mode toggle without camera/player reset, and the
  previously required shared-infrastructure UUID persistence.
- Existing W001-W003 and W002 compiler tests remain green.
- A root visual inspection must show a curved, populated Japanese suburban
  crossing composition rather than undifferentiated tracer boxes. This is
  technical review only; human Visual Acceptance remains a later approval gate.
