## Required Behavior

- Create one renderer-independent deterministic crossing simulation. It owns a
  signed/wrapped train offset, speed/progression, crossing phase, barrier
  closure, warning state, and dispensed-drink state. Renderer adapters must not
  own or advance any of these values.
- Use the phase names `open`, `approach`, `closing`, `passing`, and `clearing`.
  Derive phase, barriers, and warnings from train offset/progression rather than
  independent timers. Export named constants for thresholds, speed, initial
  offset, and the relay approach offset so tests do not duplicate magic values.
- Advance deterministically for finite non-negative `dt`, including bounded
  substeps or equivalent wrap-safe behavior for a large frame. Reject or safely
  ignore invalid/negative time without producing non-finite state.
- The relay `call-train` interaction places the train exactly at the exported
  known approach offset. From there normal stepping must visit approach,
  closing, passing, clearing, and open in order.
- The vending `dispense-drink` interaction sets a persistent visible state.
  Repeated activation is idempotent and mode switches do not clear it.
- Resolve the nearest in-range interaction from the immutable scene and player
  flat x/z state. Use the scene-owned IDs, labels, and ranges. The same resolver
  and dispatcher serve both render modes. When no target is in range, activation
  is a no-op with an explicit result.
- Add an accessible interaction prompt/control to the HUD. `E` activates the
  current in-range interaction and clicking the visible prompt does the same.
  Do not add remote backends, inventory, currency, or new interactions.
- Apply simulation state to named renderer nodes through one small shared
  presentation boundary: rigidly seat the `train-two-car` semantic root on the
  closed equatorial rail loop, rotate both barrier pivots consistently between
  open and closed, operate both warning-light nodes, and toggle one named
  `vending-machine-main-dispensed-drink` visual. Keep all named children below
  their existing semantic roots.
- Both adapters must expose compatible names for train root/two cars, both
  barrier pivots, both warning nodes, and the dispensed drink. Baseline may use
  a small conventional primitive. Voxel must use one reusable validated asset
  compiled through the existing compiler, not a per-cell Mesh path.
- Keep one simulation instance alive for the application session. Mounting or
  disposing either adapter must only rebuild adapter visuals; immediately apply
  the current simulation snapshot to a newly mounted adapter.
- Expose stable read-only DOM hooks for crossing phase, train offset, barrier
  closure, warning activity, dispensed-drink state, and current interaction ID
  and label. Hooks report the same shared state in either mode.
- Preserve the existing player collision/traversal result and all W005 state-
  preserving toggle hooks. Moving the train visual must not mutate the frozen
  scene specification or introduce renderer-specific collision logic.

## Acceptance Criteria

- Unit tests start from the relay approach offset and deterministically observe
  every phase in the required order, exact boundary behavior, wrap behavior,
  barrier closure/opening, warnings, invalid `dt`, and repeated dispatch.
- Interaction tests prove nearest/range/label behavior, out-of-range no-op,
  relay offset placement, vending persistence, and idempotence using the public
  scene and simulation APIs.
- Functional Parity tests mount both adapters independently and compare their
  public semantic IDs plus scene-owned collider bounds, interaction IDs/labels/
  ranges, animation bindings, and scene bounds. They also prove compatible named
  animation/drink nodes and identical `movePlayer` results for a fixed route.
- Renderer tests prove the dispensed-drink visual begins hidden, becomes visible
  from the shared snapshot, and adapter disposal does not dispose simulation or
  scene state. Existing resource-ownership guarantees remain green.
- Browser coverage uses the actual movement, in-range prompt, and `E`/click
  activation path—not a test-only teleport or direct simulation hook. In one
  session it activates relay and vending in each renderer, toggles during an
  active crossing sequence, observes progression rather than reset, and proves
  the dispensed drink survives both toggle directions.
- Existing W001-W005 tests, build, and browser smoke remain green. No W007
  benchmark sampler, percentile/export logic, deployment, or performance
  conclusion is introduced.
