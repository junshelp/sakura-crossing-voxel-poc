## Required Behavior

- Implement a final `VoxelAdapter` that consumes the same immutable scene object
  as Baseline Mode. The adapter must not own colliders, interactions, player
  state, train/crossing simulation, or Continuous Infrastructure.
- Provide deterministic, validated Voxel Assets or deterministic asset-builder
  outputs for the approved rendered inventory: crossing equipment, two-car
  train shell, shop, two distinct houses, vending machine, relay box, utility
  poles, fence, four cherry trees, parked bicycle, marker, and restrained petal
  treatment. Shared planet, road, footway, rails, and wires remain outside both
  adapters and must not be duplicated.
- Author on the canonical 0.25 m grid using palette IDs and explicit opaque,
  transparent, and emissive surface classes. Keep gameplay fields out of Voxel
  Asset data and validate every generated asset at its boundary.
- Prefer reusable archetype assets/compiled geometry for repeated entities such
  as cherry trees, poles, train cars, and common rig parts. Asset generation must
  be deterministic and bounded; use shells/details rather than needlessly solid
  large volumes.
- Every voxel surface must reach Three.js only through `compileVoxelAsset` and
  `surfaceGroupToBufferGeometry`. No occupied voxel may create an individual
  Three.js Mesh, Object3D, material, or texture.
- Use one shared vertex-color opaque material across all voxel chunks, plus at
  most one shared transparent and one shared emissive material path. Additional
  non-voxel material is allowed only for the single shared pixel-sign atlas and
  one restrained batched petal path.
- Create exactly one small pixel-sign atlas texture for shop/vending/relay
  signage, with nearest min/mag filtering. All sign planes must reference that
  same texture; no per-sign Canvas/DataTexture/material allocation.
- Name every semantic entity root by the existing entity ID. Name chunk/surface
  objects deterministically and retain geometry bounding boxes/spheres with
  `frustumCulled = true`.
- Preserve animation-ready parity: Voxel Mode exposes the same named crossing
  barrier pivots/warning-light nodes and exactly two named train car/pivot nodes
  expected by W006. Voxel rig children must remain seated beneath their semantic
  entity root.
- Rigidly seat each semantic root on the W003 sphere using the same center-y to
  footprint convention verified in W004. Do not project/subdivide compiled
  buffers after W002; seat small asset groups rigidly.
- Restrained petals may use one batched Points or InstancedMesh path when doing
  so avoids scattered one-cell chunk draws. It remains an entity-owned visual,
  uses the shared deterministic seed, and must not create a per-petal Mesh.
- Mode switching must preserve live player x/z/yaw/pitch/eye height, active
  fixed-camera marker, Continuous Infrastructure UUID/child count, and the same
  `SAMPLE_SCENE` reference. Rebuild and dispose only adapter-owned visuals.
- Expose stable read-only DOM hooks for Voxel semantic count, Voxel chunk mesh
  count, unique adapter material count, atlas texture count, and current renderer
  draw calls so browser tests can inspect batching direction.
- At a fixed camera after a short settle, Voxel Mode should use fewer renderer
  draw calls than Baseline Mode in the same session. This is preliminary W005
  evidence only; W007 owns formal warm-up, sampling, thresholds, and conclusions.

## Acceptance Criteria

- Asset tests validate every generated asset, required semantic/archetype
  coverage, canonical grid/bounds, deterministic byte-equivalent output, and no
  gameplay fields.
- Renderer tests prove all required semantic entity roots exist, shared
  infrastructure kinds are absent, the two train cars and crossing rig names
  match Baseline, and representative entities are rigidly seated at the correct
  local footprint.
- Tests prove repeated entities reuse compiled geometry identities, all Voxel
  chunks share no more than the approved material paths, every chunk has finite
  bounds and frustum culling, and exactly one nearest-filtered atlas texture is
  shared by all signs.
- Disposal tests prove each owned unique geometry/material/texture is disposed
  exactly once and no shared world/Baseline resources are disposed.
- Static source checks find no voxel-cell loop that constructs `THREE.Mesh`,
  `THREE.Object3D`, material, canvas, or texture per occupied cell/sign.
- Browser smoke captures Baseline draw calls, activates Voxel Mode, observes the
  complete Voxel semantic hook, confirms lower Voxel draw calls, and proves
  player/camera/infrastructure state did not reset. Toggle back to Baseline and
  retain the same state.
- Existing W001-W004, W002 compiler, gameplay, and Baseline tests remain green.
- Root fixed-camera captures show recognizable voxel crossing, two-car train,
  buildings, cherry silhouettes, signage, local rails, and no missing/chunk-seam
  gross failures. Human Visual Acceptance remains pending.
