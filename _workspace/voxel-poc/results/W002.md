# W002 Implementation Result

## Status

IMPLEMENTED

## Summary

Implemented the browser-independent Voxel Asset validator, canonical 0.25 m / 32-cell chunk constants, global occupancy-aware chunk partitioning, hidden-face removal, deterministic greedy surface compilation, and a Three.js BufferGeometry conversion boundary. Each chunk now emits at most one indexed group per surface class while preserving palette IDs/colors per vertex. Added invariant coverage for validation, meshing, winding, merging, a complete hollow shell, palette/surface groups, negative coordinates, chunk seams, deterministic ordering, and geometry bounds.

## Files Changed

- `src/voxel/asset.ts` — strict runtime Voxel Asset validation, normalized palette colors, bounds validation, and canonical constants.
- `src/voxel/compiler.ts` — deterministic floor-partitioned chunks, global neighbor checks, greedy exposed-face groups, one indexed group per surface class, palette IDs, colors, normals, and culling bounds.
- `src/voxel/three-geometry.ts` — isolated compiled-surface-group to indexed Three.js `BufferGeometry` adapter with computed bounds.
- `src/voxel/index.ts` — public voxel module exports.
- `tests/voxel/compiler.test.ts` — validator, compiler, seam, winding, determinism, surface-class, and Three.js adapter tests.
- `_workspace/voxel-poc/results/W002.md` — implementation handoff.

## Acceptance Evidence

- Empty assets return zero chunks; one voxel emits six outward quads with tested normal-aligned winding.
- Solid rectangular volumes merge to six exterior quads; a complete 3x3x3 shell missing only its center emits exactly six merged exterior and six cavity quads.
- Occupied interfaces are hidden even across different palette IDs/surface classes, including coordinates 31/32 across chunk boundaries.
- Negative coordinates use floor partitioning and emit correct negative bounds.
- Cell ordering is normalized by deterministic compiler traversal, producing equal serialized logical output.
- Opaque, transparent, and emissive faces compile into their corresponding groups; multiple opaque palette IDs share one per-chunk opaque group while retaining per-vertex palette data.
- Geometry conversion exposes indexed position, normal, color, and palette ID attributes and computes bounding box/sphere.
- Validator rejects non-objects, unknown fields, blank/duplicate IDs, non-integer coordinates, duplicate occupancy, unknown palette IDs, malformed colors/surface classes, invalid bounds, and gameplay-like fields.
- `src/voxel` contains no per-voxel Three.js Mesh construction; the compiler has no Three.js import.

## Assumptions or Deviations

- The canonical input shape is `{ id, palette: PaletteEntry[], cells: { x, y, z, paletteId }[] }`; palette entries accept only the canonical `surface` key.
- Palette colors accept deterministic `#RRGGBB` strings or three RGB components and normalize to unit RGB tuples. Optional integer cell bounds are validated when supplied.
- No package, configuration, W001 application, adapter, fixture, CSS, browser test, or documentation outside the allowed scope was changed.

## Unresolved Risks

- Each chunk emits one compiled group per surface class; greedy compatibility remains palette-ID-specific, and per-vertex palette IDs/colors preserve palette boundaries inside the shared group.
- Three.js adapter ownership/disposal remains with later renderer packages; this boundary only creates and bounds one geometry.
