## Implementation Summary

- Added one renderer-independent `CrossingSimulation` with wrapped signed train
  offset, wrapped progression, constant speed, derived `open`, `approach`,
  `closing`, `passing`, and `clearing` phases, fractional barrier closure,
  warning activity, and persistent dispensed-drink state.
- Exported phase thresholds, loop length, speed, initial offset, and relay
  approach offset. Invalid/negative time is a no-op; very large finite deltas
  reduce safely before multiplication can overflow.
- Added nearest/range interaction resolution from the immutable scene and flat
  player state, explicit out-of-range no-op results, and a shared dispatcher for
  `call-train` and `dispense-drink`. Scene-owned IDs, labels, and ranges remain
  authoritative.
- Added the shared runtime presentation boundary. It seats `train-two-car` on
  the closed equatorial rail loop, applies signed west/east barrier pivot poses,
  operates both warning nodes, and toggles the named dispensed-drink visual.
- Added the same named drink visual to both adapters. Baseline uses one small
  primitive; Voxel uses the reusable validated one-cell-wide, two-cell-high
  opaque body/cap `dispensed-drink` asset through the existing compiler path,
  placed beyond the vending machine's front face.
- Kept one simulation instance alive in `main.ts`, applying its current
  snapshot after every adapter mount and each frame. Added DOM data hooks for
  phase, offset, closure, warnings, drink state, and current interaction, plus
  an accessible prompt activated by `E` or click.
- Added unit, interaction, parity, renderer-node, and movement-driven browser
  coverage.

## Public Contracts

- `CrossingSimulation.snapshot` is the read-only current state.
- `CrossingSimulation.step(dt)` advances finite non-negative seconds.
- `CrossingSimulation.activate(id)` handles only approved interaction IDs.
- `resolveInteraction(SAMPLE_SCENE, player)` returns the nearest in-range
  scene-owned target or `null`.
- `activateCurrentInteraction(simulation, scene, player)` resolves and
  dispatches with an explicit out-of-range result.
- `applySimulationSnapshot(adapterRoot, snapshot)` is the sole visual-binding
  boundary shared by both adapters.

## Phase Constants and Derived Poses

- `TRAIN_LOOP_LENGTH = PLANET_CIRCUMFERENCE`
- `TRAIN_SPEED = 12`
- `TRAIN_INITIAL_OFFSET = -120`
- `TRAIN_APPROACH_OFFSET = -48`
- Closing begins at `-20`, passing at `-8`, clearing at `12`, and open at `32`.
- Barrier closure is `0..1`: closing interpolates up, passing is `1`, clearing
  interpolates down. `barrierClosed` is true only at `1`; warnings are active
  for every non-open phase.

## Assumptions and Deviations

- The two-car train is presented as one rigid semantic root seated and oriented
  on the equatorial loop at the current offset. This satisfies the W006 rigid
  rail-loop binding and avoids mutating scene colliders; it deliberately does
  not add a separately bent mesh representation.
- Barrier visual convention is open at signed west/east quarter-turn poses and
  closed at zero pose, with interpolation driven solely by closure fraction.
- The browser route is kept in the existing single Playwright spec so the
  repository's `npm test --exclude tests/e2e/**` shell glob does not pass a
  second e2e file as an unintended Vitest positional argument.
