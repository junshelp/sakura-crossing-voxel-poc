# W004 Implementation Result

## Status

IMPLEMENTED

## Summary

Replaced the Baseline tracer boxes with a deterministic conventional procedural
slice built from reusable Three.js primitives and the immutable Shared Scene
Specification. The renderer now includes a seated crossing rig with named
barrier pivots and warning lights, two named train cars/pivots, shop, two house
variants, vending machine, relay box, utility poles, fence, four flowering
cherry trees, restrained petals, and a parked bicycle. Shared planet/road/
footway/rail/wire infrastructure remains outside the adapter.

Added renderer-independent flat-space player state, substepped WASD/arrow
movement, footprint bounds, AABB collision with radius-based sliding, pointer
lock look, spherical camera projection, fixed comparison markers, shared
lighting, and live HUD telemetry. Mode switching rebuilds only the adapter and
preserves player/camera state and Continuous Infrastructure.

## Acceptance Evidence

- Shared road and footway now run north/south through the crossing with the
  footway offset to x=4.5 outside the coarse crossing collider. Barrier arms
  point inward from their roadside pivots. The planet is opaque and lit so the
  far-side rail loop is depth-occluded. The train starts at x=-12 for useful
  fixed-camera composition while retaining its rail-aligned east/west layout;
  the north fence is at z=29 so the railway marker is not trapped.
- Corrected the narrowly amended W003 rail-axis defect: railway points now use
  `surfacePosition(angle * PLANET_RADIUS, laneOffset)`, so angle zero is at the
  top-origin crossing and increasing angle follows authored +x/east. Closure,
  radius, gauge, top position, tangent direction, and projection equivalence
  are covered by planet regression tests.
- Baseline mounts every non-continuous semantic entity with stable root names;
  tests verify the crossing pivots/lights, exactly two train cars and pivots,
  bounded reusable materials, and absence of duplicated ground/road/footway/
  rail/wire roots.
- Entity groups are rigidly seated through the W003 planet API. Tests verify a
  representative non-origin tree lies on the radius-160 surface, its trunk and
  a house body's footprint meet the surface, and child transforms remain
  present.
- Player tests verify forward/strafe movement, yaw/pitch input behavior,
  pitch clamping, spec-bound footprint clamping, building and pole collision
  with diagonal sliding, and that the ground support collider is excluded.
  Movement uses `SAMPLE_SCENE` colliders only and is substepped to avoid
  tunneling on large frame deltas; renderer code has no collider/interactions/
  simulation definitions.
- The HUD exposes live frame time, draw calls, and triangles. Three fixed marker
  buttons and keys 1/2/3 update the shared player/camera state and
  `data-active-marker`; first movement after a fixed view restores normal eye
  height and free movement.
- E2E smoke verifies the 17 baseline semantic roots, telemetry, fixed-camera
  activation, live player x/z/yaw/pitch preservation through mode toggle, and
  unchanged Continuous Infrastructure UUID/child count.

## Assumptions or Deviations

- The Voxel adapter remains a tracer by W004 design; final voxel rendering is
  W005's responsibility.
- Baseline uses a small role palette and shared `MeshStandardMaterial` objects;
  petals use one bounded `PointsMaterial` path. No gameplay fields are attached
  to adapter objects.
- Shared train transform was corrected from an off-rail flat position to
  `[-12, 1.2, 0]`, preserving its semantic identity and east/west car layout.
- The rail function name remains backward-compatible even though its corrected
  path is a top-origin east/west loop rather than a far-side equatorial circle.

## Unresolved Risks

- Procedural baseline silhouettes are technical proof geometry and still need
  human Visual Acceptance for Japanese suburban identity and blossom-season
  composition.
- The shared infrastructure uses lightweight tracer tubes; W005 must preserve
  these exact shared resources while replacing only voxel-owned content.
- Pointer lock is intentionally desktop-only, consistent with the PRD's
  out-of-scope mobile/gamepad controls.
